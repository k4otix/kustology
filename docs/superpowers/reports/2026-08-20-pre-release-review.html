Kustology 0.2.0 Release Review

A pre-tag review of main @ 26a5da3 covering IR soundness, completeness of representation, attribute population under schemaless and schema-bound parses, Tier 1 correctness, documentation and examples, tests, CI and packaging.

Method: a lead pass plus seven independent Opus reviewers (builder, binder, Tier 1/CLI, hash/canonical/LLM view, docs/examples, tests/CI/packaging, and an empirical sweep of 209 queries × 3 build modes). Every finding below was reproduced by running code; overlapping findings are merged and the lead re-verified each high-severity item. Repro scripts: scratchpad/{lead,agentA..G}/.

Not ready to tag. The baseline is green — 442 tests, ruff, mypy, SyntaxKind audit, 7 examples, uv lock --check, wheel/sdist build and twine check all pass. None of that sees what follows: three classes of crash on valid KQL, two hash-soundness defects (one of them host-timezone dependence), a family of wrong-answer bugs in the schema binder, a systemic comment-trivia bug across the Tier 1 analyzers, and three release-pipeline gaps.

P0 — release blockers

Anything here either raises on valid KQL, returns a wrong answer with no signal, makes semantic_hash unsound, or breaks the release itself.

Crashes on valid KQL

K01Critical

Non-literal row counts raise ValueError from safe_int

src/kustology/ir/builder.py Take/Sample/Top/TopHitters/SampleDistinct branches; _builder_helpers.safe_int; TakeOp.count: int
let n = 10; T | take n          → ValueError: Expected integer literal for take/sample/top count, got ' n'
T | take toscalar(U | count)    → same          let n = 5; T | top n by x   → same          T | take 5.0 → same

All parse with zero diagnostics; let N = toscalar(...); … | take N is idiomatic Sentinel. One such rule aborts a corpus run through to_ir() and the CLI.

FixWiden count to int | AnyExpr (or add count_expr) on the five operator models and never raise from the builder; as a floor, degrade to UnknownOp.
K02Critical

Two operators in HANDLED_OPERATOR_KINDS cannot be built at all

builder.py:690 (n.ValueExpression), builder.py:600-601 (n.Expression/n.Subquery on PartitionBy)
SecurityEvent | top-hitters 10 of Account by Cnt  → AttributeError: 'TopHittersOperator' object has no attribute 'ValueExpression'
SecurityEvent | __partitionby Computer (take 1)   → AttributeError: 'PartitionByOperator' object has no attribute 'Expression'

The real members are Expression / OfExpression / ByClause.Expression and Entity / Subquery. This is the case-sensitive-member trap AGENTS.md documents, except direct attribute access raises instead of defaulting — and tests/test_reflection_audit.py only scans getattr/hasattr, not ast.Attribute. TopHittersOp also has no field for the of column, so top-hitters 5 of X by Y and top-hitters 5 by Y would still collapse after the one-word fix. Neither operator appears in any fixture or test; ~20 builder branches have zero coverage.

FixRead the correct members; add of to TopHittersOp; extend the reflection audit to direct attribute access (it finds exactly these); add a smoke test that builds one query per HANDLED_OPERATOR_KINDS member and asserts a non-UnknownOp result.

semantic_hash soundness

K03Critical

semantic_hash, LiteralExpr.value and ticks depend on the host timezone for datetime literals

src/kustology/ir/_builder_helpers.py:212 — raw.ToString("o") / raw.Ticks on a DateTimeKind.Local value
T | where d > datetime(2024-01-01T00:00:00Z)
TZ=UTC              value 2024-01-01T00:00:00.0000000+00:00  ticks 638396640000000000  hash …d453e6903337
TZ=America/New_York value 2023-12-31T19:00:00.0000000-05:00  ticks 638396460000000000  hash …77e2c5a4f352
TZ=Asia/Tokyo       value 2024-01-01T09:00:00.0000000+09:00  ticks 638396964000000000  hash …9dd4117f8270
datetime(2024-01-01) vs datetime(2024-01-01T00:00:00Z)  → different hash on every non-UTC host (same instant in KQL)

The culture axis was pinned this release; the timezone axis was not, and it produces exactly the failure the CHANGELOG says was closed ("making the hash machine-dependent"). It also falsifies "ticks is the only lossless form". A dedup index built on one runner will not match one built on another.

FixToUniversalTime() when Kind == Local, SpecifyKind(Utc) when Unspecified, before formatting and reading Ticks. Add a TZ=Asia/Tokyo leg to the de-DE/fr-FR CI matrix. Still inside the unreleased kustology-sem-v2 window.
K04Critical

normalize_expressions rewrites tolower(X) == R → X =~ R for any R — unsound, and baked into the hash

src/kustology/ir/_normalize.py:50-57, applied in compute_semantic_hash
T | where tolower(X) == "Y"    hashes EQUAL to   T | where X =~ "Y"     (always-false vs live predicate)
T | where tolower(X) == Col    hashes EQUAL to   T | where X =~ Col
"y" == tolower(X)              not rewritten (asymmetric);  toupper(X) == "y"  no rule at all
FixFire only when the other operand is a string literal equal to its own .lower() (or itself a tolower(...)); handle the mirrored operand order; add the toupper twin under the same guard. Verified sound and unaffected: not(not(X)), And/Or flattening, and the deliberate absence of not(a == b) → a != b.

K06High

Four more hash-robustness defects

transforms.py _VOLATILE_FIELDS/_strip_volatile_fields/_normalize_node; llm_view._OMIT_FIELDS
  • body_span. LetFunction.body_span is not stripped (only the key span is) — a comment before let f = (x:int){x+1}; T | extend y = f(a) changes the hash; it also leaks into to_llm_dict as {"kind":"Span",…}.
  • raw_text trivia. ScanOp/TopNestedOp/MakeGraphOp/MacroExpandOp/Graph*Op/Unknown* hash raw_text that includes leading whitespace and comments — T | top-nested 3 of a by max(b) ≠ T\n| top-nested ….
  • Key-name stripping. _strip_volatile_fields deletes keys named table/span/result_type/result_schema from any dict, including user column names in AssertSchemaOp.columns/ParseKvOp.columns: assert-schema (a:long, table:long) ≡ assert-schema (a:long).
  • Root double negation. normalize_expressions discards the replacement node at the root, so compute_semantic_hash(pred) for not(not(a==1)) ≠ for a==1, while the same predicates inside a FilterOp hash equal.
FixStrip by model field (walk the copied models and clear volatile attributes) instead of by key name; add body_span to both strip sets; normalize raw_text whitespace/comments at build; have normalize_expressions return the possibly-replaced root and rebind it.
